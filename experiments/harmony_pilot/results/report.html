JazzSAMBA: first harmonic-matching pilot

Completed diagnostic, not a position tracker. Three songs, preferred and alternate takes, 18 separate bass/saxophone/trumpet MIDI files. No piano or drums, no training, no learned weighting. Primary tables below use preferred takes only. All 384 conditions and alternate results are in the CSV files.

What was computed

Every 100 ms, collect pitch classes from a trailing window and compare them with every distinct chord label in that song's chart. Templates are twelve-element vectors; cosine similarity measures how well their pitch classes match. Timing labels are used for evaluation, never to reset the input window or tell the matcher which chord comes next.

  • Binary template: written chord tones and explicit alterations have weight 1; other notes 0.
  • Soft extension template: explicit tones remain 1; selected unaltered extensions receive 0.25 and other pitches 0.05. This is a deliberately simple, fully documented heuristic, not a reproduction of Maezawa, CHORD, or a uniquely correct chord-scale mapping.
  • Inputs: bass; both horns; all three pooled; or all three with each active instrument normalized to equal total mass. Equal-instrument normalization is fixed, not adaptive learning.
  • Context: 0.5, 1, 2, and 4 seconds. Onset counts versus elapsed note duration, clipped at the current time. Primary setting was declared as two-second onset counts before examining results.

Does adaptive selection have room to help?

An oracle that uses the correct labels to select an already correct bass-only, horns-only, or pooled prediction reaches 34.7% under the primary soft-template setting. This shows some complementary decisions. It is not a learned result, does not prove the selector is learnable, and is not an upper bound for all possible score-level fusion methods.

What we can conclude

  • Adding the available horn notes modestly improves aggregate compatibility over bass alone; it does not produce reliable chord recognition.
  • Soft extensions give only a small average improvement. The input representation, context length, source availability, and annotation correspondence warrant attention before a larger weighting model.
  • Several different labels receive the same best score. G-6 and E-7b5 even have identical binary pitch-class templates. An uncertain compatibility distribution is more appropriate than treating every top label as certain.
  • The next controlled comparison should add the missing piano MIDI while keeping the same templates and evaluation. A learned root-relative pitch-class profile is a subsequent alternative, trained only on other songs.

Boundaries and verification

  • Three deliberately selected exploratory songs, not independent model-selection and test sets. No claim of generalization.
  • Official annotation JSONs describe preferred performances. Alternate evaluation uses the release's documented copied async grid and is kept as exploratory.
  • Original timing origins are preserved; no time shift was fitted to improve matching. Audio and annotation alignment were not independently verified. Played substitutions, anticipation, transcription errors, or reference errors can reduce compatibility.
  • Initial padding and the terminal zero-length Tunisia chord are excluded, as are note tails outside labeled intervals. No labeled transition frames are otherwise discarded.
  • All note velocities are 100. Dynamics and pedal cannot provide evidence in these files.
  • All files have one musical note track plus metadata. Instrument identity comes from the filename, since all note channels are zero.
  • The checks cover future-note/duration invariance, timing conversion, root spelling, chord alterations, and annotation continuity. Full MIDI and annotation hashes are saved.
  • Offline vectorized runtime is not streaming latency. No beat tracker, positional filter, recovery benchmark, or adaptive network was evaluated.
